# Chef AI Workspace — アーキテクチャ初稿

**Status:** v0.2（基本方針承認済み・詳細方式は未決定）  
**Based on:** [MVP.md](MVP.md)  
**Scope:** Meta APIの認証復旧を待たずに確定済み原則から設計できる範囲

## 1. 目的と非目的

料理人の自然言語によるアイデアを、確定・仮設定・未確定を保持した構造化レシピに変換し、反復編集・概算原価計算・保存・再取得できるようにする。

- 今回の独立プロジェクトは既存の非公開Ricetta-OSに依存しない。
- 単なるチャット履歴をレシピの唯一の保存形式にしない。
- AIの推定価格・計算結果を確定データとして扱わない。
- まだ選定していないWebフレームワーク、DB、音声認識方式は本書で決定しない。

## 2. 処理経路（論理構成）

```text
音声入力 ── 音声認識 ─┐
                     ├→ ユーザー発話
テキスト入力 ─────────┘      │
                             ▼
                      アプリ側 Orchestrator
                             │
                  （現在のレシピ状態と指示）
                             ▼
                       Meta AI Model
                  意図解釈・補完・変更提案
                             │
                    構造化された提案
                             ▼
                  検証／整合性チェック
                             │
                    有効な変更だけ適用
                             ▼
                        Recipe State
                             │
                   決定論的な原価計算
                             │
                      表示・保存・履歴
```

**原則:** AIは状態を直接書き換えず、変更案を返す。永続化と計算はアプリ側の責務。正常に解釈できない変更は既存状態を壊さない。

## 3. レシピ状態の最小構成（案）

- `recipe_id`：レシピを識別するID
- `name`：料理名
- `yield`：出来上がり人数・数量（不明な場合あり）
- `ingredients[]`：レシピ材料行。各行に固有IDを持たせ、自然言語の修正対象を識別
- `instructions[]`：調理工程
- `selling_price`：売価
- `cost_adjustment`：指定された概算調整額（食材原価とは分離）
- `version`：保存時の版または変更競合を検知するための番号（方式は未決定）

レシピ材料行の候補フィールド：

- `material_name`：レシピに記述する材料名。購入商品名とは区別する
- `quantity` / `unit`：使用数量・単位
- `ingredient_id`：共通食材への任意参照（未紐付けを許容）
- `estimated_unit_price` / `price_unit`：未紐付けでも概算できる単価と基準単位
- `notes`：用途に必要な補足

### 材料名・共通食材・仕入商品の分離（採用方針）

- **材料（Recipe Material）**：各レシピの表記と使用量。「でんぷん」「片栗粉」など自由に記述できる。共通食材の登録を要求しない
- **共通食材（Ingredient）**：複数レシピから参照可能な実際の使用食材。参照IDと現在の標準単価を持たせる余地を残す
- **仕入商品（Purchased Product）**：仕入先・商品規格などの購買対象。MVPでの本格的なマスター・仕入先管理は対象外

同じ共通食材を参照している場合、将来その仕入商品・標準単価を変更すれば、参照レシピの**現在原価**に変更が伝播できる設計とする。ただし、これは自動更新機能をMVPで必ず実装するという意味ではない。

レシピ材料の表示名と参照食材名は一致する必要がない。紐付けなしのレシピ作成・概算計算・保存を阻害してはならない。

**現在原価と保存時原価は別:** 共通食材の価格が変更されても、保存されたレシピ版の計算根拠・概算原価スナップショットは保持する。新しい単価による現在原価の再評価は別に行い、過去の版を暗黙に書き換えない。

**単価の優先規則・価格スナップショット・参照更新タイミング**は次段階で具体的に決める。

値ごとに次の区分を保持する。

| 区分 | 意味 | 計算への扱い |
|---|---|---|
| 確定（confirmed） | 料理人が明示・確定した値 | 入力として利用 |
| 仮設定（assumed） | AIやアプリが仮置きした値 | 概算に利用し、仮設定であることを表示 |
| 未確定（unresolved） | 根拠が足りず設定できない値 | 勝手に数値化しない。算出不能項目を明示 |

区分は**食材行全体ではなく、数量・単価など個々の値**に付ける。例えば「海老3尾」は確定でも「海老単価」は仮設定となり得る。

## 4. 変更提案と検証の契約（設計案）

Meta AI Modelは自由文から、レシピへの操作（例：食材追加・数量変更・単価変更・別版保存・検索）を構造化して返す。

アプリは少なくとも以下を確認してから適用する。

1. 操作の種類がサポート対象に含まれる
2. 変更対象のレシピ・食材行が特定できる
3. 数量・通貨・単位の形式が妥当
4. 変更後も確定／仮設定／未確定の区分が維持される
5. 提案が現在のレシピ版に対して有効である

曖昧な対象（同じ海老が複数行など）や単位換算不能な値は、無条件に反映しない。必要な場合のみ短く確認する。

## 5. 原価計算の責務

原価計算は構造化済み数値に対して決定論的に実行する。

- 食材行原価 = 使用量 × 単価（単価の数量・単位基準へ正規化してから計算）
- 食材原価合計 = 計算可能な食材行原価の合計
- 概算原価 = 食材原価合計 + 明示された調整額
- 原価率 = 概算原価 ÷ 売価 × 100（売価が有効なときのみ）

未確定または換算不能な食材行がある場合は、計算済み合計を**完全な総原価と表示しない**。不足情報のある部分を別途示す。

「原価を50円高めに見積もって」は食材の仕入単価を勝手に書き換えず、原価調整額として区別する案とする。この仕様の最終決定はレビューで行う。

## 6. MVPの通しシナリオ

1. 海老のパスタを自然言語で入力する。
2. Meta AIがレシピ初期値と仮設定を提案する。
3. アプリが検証し、状態を生成・表示する。
4. 「海老を4尾にして」で数量だけを更新する。
5. 「1尾150円」で単価を更新し、原価・原価率を再計算する。
6. 「別バージョンで保存」で元の版を残し派生版を保存する。
7. 保存したレシピを自然言語から検索・再取得する。
