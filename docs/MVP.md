# Chef AI Workspace — MVP Specification

**Status:** Draft v0.1  
**Purpose:** Meta Global AI Developer Hackathon 2026

## 1. MVP Goal

料理人が自然言語で料理のアイデアを入力し、AIによる補完を受けながら、原価計算可能なレシピを作成・修正・保存・再取得できること。

## 2. Core Workflow

1. 料理人が音声またはテキストで料理のアイデアを伝える。
2. Meta AIモデルが内容を解釈し、レシピの構造化や変更内容を提案する。
3. アプリが提案内容を検証する。
4. レシピの構造化データを更新する。
5. 決定論的なプログラムで原価・原価率を計算する。
6. レシピと必要な状態情報を保存する。
7. 後から自然言語でレシピを検索・再編集する。

## 3. MVP Functional Requirements

### F-01: Natural Language Recipe Creation

料理の説明から、料理名、食材、分量、価格、売価、調理工程などを抽出・構造化する。

### F-02: Assumption Management

情報を「確定」「仮設定」「未確定」に区別する。

仮設定による概算を許可するが、確定値と混同しない。

### F-03: Conversational Editing

料理人が自然言語で食材、数量、単価、売価などを変更できる。

変更対象の誤認や不整合を防ぐため、提案内容はアプリ側で検証する。

### F-04: Deterministic Cost Calculation

構造化された数量・単価に基づいて、原価と原価率を計算する。

AIが計算結果を直接決定しない。

### F-05: Recipe Persistence

レシピを保存し、再取得できる。

保存後の変更にも対応する。

### F-06: Recipe Versions

既存レシピを元に別バージョンを作成・保存できる。

### F-07: Conversational Retrieval

料理名や会話上の手掛かりによって、保存済みレシピを呼び出せる。

### F-08: Voice Input

スマートフォンから音声でレシピ作成や変更指示を入力できる。

## 4. AI Responsibilities

- 自然言語の解釈
- レシピ情報の抽出
- 不足情報の補完
- 変更意図の推定
- 必要な確認質問の判断
- 調理工程の生成・編集

## 5. Application Responsibilities

- 変更提案のスキーマ検証
- レシピ状態の更新
- 数量・単価の扱い
- 原価計算
- データの永続化
- バージョン管理
- 確定・仮設定・未確定の区別の維持

## 6. MVP Acceptance Scenario

次の一連の操作が成立することを受け入れ基準とする。

1. 「海老のパスタを考えている」と自然言語で入力する。
2. 食材、数量、参考価格、調理工程を含むレシピが表示される。
3. AIの補完値が仮設定として区別される。
4. 「海老を4尾にして」で数量が変更される。
5. 「1尾150円」で単価と原価が再計算される。
6. 「別バージョンで保存」で派生レシピが保存される。
7. 保存したレシピを自然言語で再取得できる。
8. これらの主要操作をスマートフォンから実行できる。

## 7. Constraints

- 既存の非公開Ricetta-OSへの依存を設けない。
- Metaモデルを実際のAI処理経路に組み込む。
- 推定値を確定値として扱わない。
- 通常のレシピ作成を細かな入力フォームに依存させない。
- AIの出力を検証せずに正式なレシピ状態へ反映しない。

## 8. Open Technical Decisions

- フロントエンド構成
- バックエンド構成
- MetaモデルとAPIの選択
- 音声認識方式
- データ保存方式
- レシピ変更操作のデータ形式
- バージョン保存方式
- デプロイ方式

これらはアーキテクチャ設計段階で決定する。
